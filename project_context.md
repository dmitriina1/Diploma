# Проект: Информационная система интеллектуального анализа видеоконтента для формирования базы вопросов IT-собеседований

## Общая информация
- **Название проекта**: Interview Prep — Извлечение вопросов для собеседований из YouTube.
- **Цель**: Автоматизация подготовки к IT-собеседованиям путём извлечения вопросов из YouTube видео с записями реальных интервью.
- **Технологии**: Docker, FastAPI, React, PostgreSQL, Redis, Whisper, LLM (OpenRouter, Groq, Gemini), n8n, Nginx.
- **Масштабируемость**: Поддерживает горизонтальное масштабирование Whisper сервиса через Docker Compose.

## Архитектура
Проект использует микросервисную архитектуру с контейнеризацией:

### Сервисы
1. **PostgreSQL**: База данных для хранения вопросов, задач обработки и обработанных видео.
   - Таблицы: `questions`, `processing_tasks`, `processed_videos`.
   - Скрипт инициализации: `scripts/init-db.sql`.

2. **Redis**: Кэширование задач и результатов.

3. **n8n**: Оркестрация workflow для обработки видео.
   - Автоматически импортирует и активирует workflow из `n8n/workflows/youtube-questions.json`.
   - Использует PostgreSQL для хранения состояния.

4. **Whisper Service**: Микросервис для транскрибации аудио.
   - Использует `faster-whisper` (CTranslate2) для быстрой транскрибации на CPU.
   - Масштабируется через `--scale whisper=N`.
   - CPU_THREADS рассчитываются динамически: `16 / N` потоков на реплику.
   - Entrypoint: `entrypoint.sh` для автоматического определения количества реплик.

5. **Nginx Load Balancer**: Балансирует нагрузку между репликами Whisper.
   - Конфигурация: `nginx/nginx.conf`.
   - Стратегия: `least_conn`.

6. **Backend (FastAPI)**: Основной API-сервер.
   - Эндпоинты: `/api/process-video` для обработки видео, `/health` для проверки здоровья.
   - Интеграция с LLM для извлечения вопросов.
   - Поддержка нескольких провайдеров: OpenRouter, Groq, Gemini, Ollama.
   - Переменная `LLM_PROVIDER` для выбора провайдера.

7. **Frontend (React)**: Пользовательский интерфейс.
   - Порт: 3000.
   - Отправляет YouTube URL на backend для обработки.

### Переменные окружения (.env)
- `DATABASE_URL`: URL для PostgreSQL.
- `REDIS_URL`: URL для Redis.
- `N8N_WEBHOOK_URL`: URL для webhook n8n.
- `WHISPER_SERVICE_URL`: URL для Whisper сервиса.
- `WHISPER_POOL_SIZE`: Количество реплик Whisper (по умолчанию 2).
- `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`: Ключи для LLM.
- `LLM_PROVIDER`: Выбор провайдера (auto, openrouter, groq, gemini, ollama).
- `WHISPER_MODEL`: Модель Whisper (по умолчанию medium).

### Ключевые файлы
- `docker-compose.yml`: Оркестрация всех сервисов.
- `README.md`: Документация проекта.
- `backend/main.py`: Основной код backend с API и логикой обработки.
- `whisper-service/main.py`: Код Whisper сервиса.
- `whisper-service/entrypoint.sh`: Скрипт для динамического расчёта CPU_THREADS.
- `frontend/src/App.js`: Основной компонент React.
- `scripts/init-db.sql`: Инициализация базы данных.

### Текущий функционал
- Отправка YouTube URL через frontend.
- Скачивание аудио и субтитров через yt-dlp.
- Транскрибация через Whisper (гибридная: субтитры + ASR).
- Извлечение вопросов через LLM.
- Сохранение результатов в БД.
- Масштабирование Whisper для ускорения обработки.

### Масштабирование
- Whisper: `docker-compose up -d --scale whisper=N` (N до 8+ в зависимости от ресурсов).
- Backend/Frontend: Можно масштабировать аналогично.
- Для продакшн: Kubernetes или Docker Swarm.

### Безопасность и отказоустойчивость
- Поддержка нескольких LLM-провайдеров для резервирования.
- Healthchecks для всех сервисов.
- Логирование и обработка ошибок.

## План развития (новые требования)
### 1. PublicSide
- **Описание**: Публичная страница для отображения всех вопросов из БД.
- **Функционал**:
  - Список вопросов с фильтрами (по теме, сложности, вероятности).
  - Отображение вероятности выпадения вопроса (% от обработанных видео).
- **Реализация**:
  - Новый маршрут в backend: `/api/questions` для получения вопросов.
  - Обновление frontend: Добавить компонент PublicSide с таблицей вопросов.
  - Добавить поле `probability` в таблицу `questions` (расчёт: количество видео с вопросом / общее количество видео * 100%).

### 2. AdminPanel
- **Описание**: Панель для администраторов.
- **Функционал**:
  - Отправка YouTube URL для обработки.
  - Просмотр списка извлечённых вопросов.
  - Редактирование/удаление/добавление вопросов.
  - Одобрение вопросов (все или по одному).
  - Рядом с каждым вопросом: цифра похожих вопросов из БД.
  - При клике на цифру: список похожих вопросов; выбор одного заменяет текущий вопрос.
- **Реализация**:
  - Новый маршрут в backend: `/api/admin/questions` для CRUD операций.
  - `/api/admin/process-video` для обработки URL.
  - `/api/admin/approve-questions` для одобрения.
  - Логика поиска похожих вопросов: Использовать LLM для семантического поиска или простой текстовый поиск (например, через embeddings или cosine similarity).
  - Обновление frontend: Добавить компонент AdminPanel с формами и таблицами.
  - Добавить поле `approved` в таблицу `questions`.

### 3. Расчёт вероятности
- **Описание**: Вероятность = (количество видео с вопросом / общее количество обработанных видео) * 100%.
- **Реализация**:
  - Добавить таблицу `question_video` для связи вопросов и видео.
  - При одобрении вопроса обновлять связи.
  - Расчёт вероятности при запросе вопросов.
