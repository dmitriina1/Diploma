# Архитектура v2.0 — Краткое резюме изменений

## 🎯 Главная идея

**Вы были правы!** Разбивать аудио на части и склеивать — это неэффективно и снижает качество.

**Правильная модель:** 1 мощный Whisper обрабатывает 1 полное аудио. Если приходит еще задача → поднимается еще Whisper для другого аудио.

---

## ✅ Что было убрано

### 1. **n8n** ❌
- Лишняя прослойка между frontend и backend
- Просто вызывала internal эндпоинты по очереди
- Добавляла сложность без пользы

### 2. **Nginx Load Balancer для Whisper** ❌
- Не нужен для per-task модели
- Балансировал между воркерами, которые обрабатывали части одного аудио

### 3. **WhisperPool с разделением аудио** ❌
- Резал аудио на N частей
- Отправлял параллельно на N воркеров
- Склеивал результаты с overlap
- **Проблема:** Потеря контекста и качества на стыках

### 4. **Internal эндпоинты** ❌
- `/internal/download-audio`
- `/internal/transcribe`
- `/internal/extract-questions`
- `/internal/save-questions`
- Были нужны только для n8n

## ✅ Что добавлено

### 1. **WhisperOrchestrator**
- Управляет пулом Whisper-воркеров
- Распределяет задачи между воркерами
- Динамическое масштабирование (по требованию)

**Логика:**
```
Задача 1 → есть свободный воркер? → да → отправить на него
         → нет → можно создать новый? → да → создать и отправить
              → нет (лимит) → ждать освобождения
```

### 2. **Прямой Pipeline обработки**
```python
async def process_video_pipeline(task_id, youtube_url, topic, level):
    1. Скачивание аудио (yt-dlp)
    2. Транскрибация ПОЛНОГО аудио через Whisper
    3. Извлечение вопросов через LLM
    4. Сохранение в БД
```

Все в одном месте, без прослоек!

### 3. **Оптимизация для AMD Ryzen 7, 32GB RAM**

**Whisper:**
- Модель: `large-v3` (лучшее качество)
- CPU threads: `10` (оптимально для R7 8 ядер / 16 потоков)
- Память: ~14GB на воркер
- Максимум: 2 воркера одновременно

**Конфигурация:**
```yaml
whisper-worker:
  environment:
    - WHISPER_MODEL=large-v3
    - CPU_THREADS=10
  deploy:
    resources:
      limits:
        memory: 14G
```

## 🚀 Производительность

### Старая версия:
- Видео 60 мин → делит на 2 части по 30 мин
- Обрабатывает параллельно на 2 воркерах
- **Проблема:** На границах частей может быть потеря контекста

### Новая версия:
- Видео 60 мин → отправляет на 1 воркер **целиком**
- Воркер видит весь контекст
- **Результат:** Лучшее качество распознавания

### Если 2 видео одновременно:
- Старая: резала оба на части, путалась
- Новая: воркер 1 обрабатывает видео 1, воркер 2 обрабатывает видео 2 ✅

## 🎓 Почему это правильно?

### 1. **Whisper работает лучше с полным контекстом**
- Language model внутри Whisper учитывает контекст
- При разделении теряется этот контекст

### 2. **Честное масштабирование**
- 1 задача = 1 воркер
- Если 2 задачи = 2 воркера (если ресурсы позволяют)
- Если ресурсов нет = очередь

### 3. **Проще = надежнее**
- Меньше движущихся частей
- Меньше точек отказа
- Легче отлаживать

### 4. **Оптимизация под ваше железо**
- R7 32GB может комфортно запустить 2 воркера по 14GB
- Каждый с 10 потоками
- Каждый обрабатывает полное аудио

---

## 📈 Когда старая версия могла быть лучше?

Только в одном случае: **очень слабое железо**

Например:
- CPU: 2 ядра
- RAM: 4GB

Тогда разделение на части позволяло "протолкнуть" длинное видео по частям.

**Но у вас R7 32GB!** Вам не нужно жертвовать качеством.
