# Архитектурный обзор проекта "Система подготовки к IT-собеседованиям"

## Введение

Данный проект представляет собой комплексную систему для автоматизированной подготовки к IT-собеседованиям на основе анализа YouTube-видео. Система извлекает вопросы из видеоконтента, осуществляет семантическую дедупликацию, рассчитывает вероятность появления вопросов и предоставляет удобный интерфейс для администрирования и использования базы вопросов.

## Общая архитектура

Проект реализован с использованием микросервисной архитектуры на базе Docker Compose, включающей 6 основных сервисов:

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   Frontend      │    │    Backend      │    │  Whisper Pool   │
│   (React)       │◄──►│   (FastAPI)     │◄──►│  (FastAPI)      │
│   Port: 3000    │    │   Port: 8000    │    │  Port: 8001     │
└─────────────────┘    └─────────────────┘    └─────────────────┘
         │                       │                       │
         ▼                       ▼                       ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   PostgreSQL    │    │     Redis       │    │     n8n         │
│   Port: 5432    │    │   Port: 6379    │    │   Port: 5678    │
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

### Архитектурные паттерны

1. **Микросервисная архитектура** - каждый компонент системы представляет собой независимый сервис
2. **API Gateway паттерн** - Nginx выступает в роли балансировщика нагрузки для Whisper сервисов
3. **Repository паттерн** - абстракция доступа к данным в PostgreSQL
4. **CQRS паттерн** - разделение операций чтения и записи для оптимизации производительности
5. **Observer паттерн** - WebSocket для real-time обновлений прогресса обработки
6. **Strategy паттерн** - различные стратегии LLM (OpenRouter, Groq, Gemini) для извлечения вопросов

## Технологии

### Backend
- **FastAPI** - высокопроизводительный веб-фреймворк для Python
- **PostgreSQL** - реляционная база данных для хранения вопросов и метаданных
- **Redis** - in-memory хранилище для кэширования и очередей задач
- **SQLAlchemy** - ORM для работы с базой данных
- **Alembic** - система миграций базы данных

### AI/ML компоненты
- **Sentence Transformers** - для создания эмбеддингов текста
- **FAISS** - библиотека для эффективного поиска по векторам (семантический поиск)
- **faster-whisper** - оптимизированная модель транскрибации с VAD
- **CTranslate2** - высокопроизводительная inference для трансформеров

### Frontend
- **React** - библиотека для создания пользовательского интерфейса
- **React Hooks** - управление состоянием компонентов
- **Fetch API** - для HTTP запросов к backend
- **WebSocket** - для real-time обновлений

### Инфраструктура
- **Docker & Docker Compose** - контейнеризация и оркестрация сервисов
- **Nginx** - reverse proxy и load balancer для Whisper сервисов
- **yt-dlp** - утилита для скачивания и обработки YouTube видео
- **FFmpeg** - обработка аудио/видео файлов

### Внешние сервисы
- **OpenRouter API** - доступ к множеству LLM моделей
- **Groq API** - высокопроизводительная inference
- **Google Gemini** - мультимодальная модель от Google
- **n8n** - платформа для автоматизации рабочих процессов

## Компоненты системы

### 1. Backend Service (FastAPI)
**Назначение:** Центральный API-сервер, координирующий всю бизнес-логику системы.

**Основные функции:**
- Обработка HTTP запросов от frontend
- Управление задачами обработки видео
- Координация с Whisper сервисами
- Работа с базой данных (PostgreSQL)
- Кэширование результатов (Redis)
- WebSocket соединения для real-time обновлений

**Ключевые эндпоинты:**
- `POST /api/process-video` - запуск обработки видео
- `GET /api/task/{task_id}` - получение статуса задачи
- `GET /api/questions` - получение вопросов с фильтрами
- `POST /api/admin/questions` - создание вопросов вручную
- `GET /api/questions/similar` - поиск похожих вопросов

### 2. Whisper Service Pool
**Назначение:** Масштабируемый сервис транскрибации аудио в текст.

**Архитектура:** Pool из нескольких реплик за Nginx load balancer для распределения нагрузки.

**Технологии:**
- faster-whisper с моделью medium (оптимизированная)
- VAD (Voice Activity Detection) для фильтрации тишины
- int8 quantization для ускорения inference

**Рабочий процесс:**
1. Получение аудио файла от backend
2. Транскрибация с временными метками
3. Возврат сегментов с текстом и таймкодами

### 3. Frontend (React)
**Назначение:** Пользовательский интерфейс для взаимодействия с системой.

**Компоненты:**
- **PublicSide** - публичная база вопросов с фильтрами и поиском
- **AdminPanel** - администрирование системы (создание вопросов, одобрение, управление)

**Особенности:**
- Responsive дизайн
- Real-time обновления через WebSocket
- Умная проверка дубликатов при создании вопросов

### 4. PostgreSQL Database
**Назначение:** Хранение структурированных данных системы.

**Основные таблицы:**
- `questions` - вопросы с ответами, темами, сложностью
- `videos` - метаданные обработанных видео
- `question_video_links` - связи вопросов с видео (many-to-many)
- `tasks` - история обработки задач

**Особенности:**
- ACID транзакции
- Индексы для оптимизации запросов
- JSON поля для гибкого хранения метаданных

### 5. Redis Cache
**Назначение:** Кэширование и временное хранение данных.

**Использование:**
- Кэширование результатов семантического поиска
- Очереди задач обработки
- Временное хранение промежуточных результатов

### 6. n8n Workflow Engine
**Назначение:** Автоматизация бизнес-процессов.

**Функции:**
- Автоматический импорт вопросов из внешних источников
- Webhook обработка для интеграций
- Планирование повторяющихся задач

## Рабочий процесс системы

### 1. Обработка YouTube видео

```
YouTube URL → yt-dlp → Audio Extraction → Whisper Pool → Transcript → LLM → Questions → Deduplication → Database
```

**Детальный процесс:**
1. **Ввод URL** - пользователь указывает YouTube видео
2. **Скачивание** - yt-dlp извлекает аудио дорожку
3. **Транскрибация** - Whisper сервис преобразует аудио в текст с таймкодами
4. **Извлечение вопросов** - LLM анализирует транскрипцию и выделяет вопросы с ответами
5. **Дедупликация** - семантический поиск объединяет похожие вопросы
6. **Сохранение** - вопросы сохраняются в базу с метаданными

### 2. Семантическая дедупликация

**Алгоритм:**
1. Создание эмбеддингов для всех вопросов (SentenceTransformer)
2. Построение FAISS индекса для быстрого поиска
3. При добавлении нового вопроса - поиск ближайших соседей
4. Если схожесть > порога - объединение вопросов
5. Обновление вероятности появления вопроса

**Формула вероятности:**
```
P(question) = (videos_with_question / total_videos) × 100%
```

### 3. Управление вопросами (Admin Panel)

**Функции:**
- Просмотр всех извлеченных вопросов
- Одобрение/отклонение вопросов
- Ручное создание вопросов с проверкой дубликатов
- Редактирование и удаление вопросов
- Замена вопросов на похожие (слияние)

### 4. Публичный доступ

**Функции:**
- Фильтрация вопросов по теме и сложности
- Поиск по тексту
- Сортировка по вероятности появления
- Просмотр источников (видео + таймкоды)

## Особенности реализации

### Масштабируемость
- **Horizontal scaling** Whisper сервисов через Nginx
- **Database optimization** с индексами и партиционированием
- **Caching strategy** для часто запрашиваемых данных

### Производительность
- **Async/await** паттерн в FastAPI для неблокирующих операций
- **Background tasks** для длительных операций (транскрибация, LLM inference)
- **Connection pooling** для базы данных

### Надежность
- **Error handling** с подробным логированием
- **Health checks** для всех сервисов
- **Graceful shutdown** контейнеров
- **Backup strategies** для базы данных

### Безопасность
- **Input validation** на всех эндпоинтах
- **Rate limiting** для API запросов
- **Environment variables** для чувствительных данных
- **Docker security** practices
