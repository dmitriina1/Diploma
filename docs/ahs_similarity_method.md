# Adaptive Hybrid Similarity (AHS) для поиска похожих вопросов

## 1. Идея метода

Метод AHS (Adaptive Hybrid Similarity) предназначен для поиска семантически и лексически близких вопросов с учетом контекста модерации.

В отличие от простого cosine Top-K, AHS объединяет несколько сигналов:
- Семантика (эмбеддинги)
- Лексическая близость строки
- Пересечение информативных токенов
- Контекстные метаданные (topic, difficulty)
- Динамический порог по специфичности запроса

## 2. Гибридный скор

Гибридная оценка кандидата c для запроса q:

$$
S_{AHS}(q,c)=\left(0.60\,S_{sem}+0.20\,S_{lex}+0.12\,S_{tok}+0.08\,S_{meta}\right)\cdot\left(0.85+0.15\,S_{len}\right)
$$

Где:
- \(S_{sem}\) - косинусная близость эмбеддингов (FAISS + normalized vectors)
- \(S_{lex}\) - строковая близость (SequenceMatcher)
- \(S_{tok}\) - пересечение токенов (Jaccard)
- \(S_{meta}\) - согласованность метаданных (topic/difficulty)
- \(S_{len}\) - согласованность длины формулировок

## 3. Адаптивный порог

Порог принятия зависит от специфичности запроса:

$$
\tau(q)=\operatorname{clip}\left(\tau_0+\alpha\cdot\max(0,0.55-Spec(q)),\,0.45,\,0.85\right)
$$

Где:
- \(\tau_0 = 0.64\) для public
- \(\tau_0 = 0.60\) для admin
- \(\alpha = 0.12\)
- \(Spec(q)\) - доля информативных токенов в запросе

Интерпретация:
- Более общий запрос -> порог повышается (меньше ложных совпадений)
- Более специфичный запрос -> порог ниже в разумных границах

## 4. Правило принятия кандидата

Кандидат принимается, если выполнено:

$$
accept(c)=\left[S_{AHS}(q,c)\ge\tau(q)\right] \lor HardDuplicate(q,c)
$$

HardDuplicate (жесткий дубль) срабатывает, если:
- очень высокая строковая близость + достаточная семантика
- или очень высокое токенное пересечение + достаточная семантика

Текущая реализация условий HardDuplicate:
- \(S_{lex} \ge 0.93\) и \(S_{sem} \ge 0.65\)
- или \(S_{tok} \ge 0.85\) и \(S_{sem} \ge 0.60\)

## 5. Дополнительная фильтрация

Используется confidence-tail pruning:
- после первичного отбора удаляется слабый "хвост" кандидатов,
- даже если кандидаты формально выше порога,
- чтобы не показывать маргинальные совпадения в конце списка.

Текущая формула хвоста:
- \(tail\_floor = \max(\tau(q), best\_score - 0.18)\)

## 6. Почему это можно защищать как научный вклад

1. Это не один сигнал, а интерпретируемый гибридный критерий.
2. Порог адаптируется к сложности текста, а не фиксирован глобально.
3. Разделены режимы public/admin (разная строгость и прикладная полезность).
4. Есть управляемый параметр min_score для воспроизводимых экспериментов.
5. Модель дает компонентные оценки (sem/lex/tok/meta), удобные для анализа и абляций.

## 7. Экспериментальный протокол для диссертации

### 7.1 Бейзлайны
- Baseline-1: cosine Top-K без порога
- Baseline-2: cosine + фиксированный порог

### 7.2 Предлагаемый метод
- AHS + adaptive threshold + hard-duplicate override + tail pruning

### 7.3 Метрики
- Precision@K
- Recall@K
- nDCG@K
- Доля ложных дублей в модерации

### 7.4 Абляционные эксперименты
- Убрать \(S_{lex}\)
- Убрать \(S_{tok}\)
- Убрать \(S_{meta}\)
- Отключить динамический порог
- Отключить tail pruning

### 7.5 Статистическая проверка
- Бутстрэп доверительных интервалов для Precision@K и nDCG@K
- Сравнение AHS против бейзлайнов на одинаковых выборках

## 8. Текущие боевые параметры в проекте (на 2026-04-19)

- Коэффициенты AHS: 0.60 / 0.20 / 0.12 / 0.08
- Множитель длины: \(0.85 + 0.15\,S_{len}\)
- Базовый порог public: 0.64 (64%)
- Базовый порог admin: 0.60 (60%)
- Диапазон адаптивного порога: 0.45..0.85 (45%..85%)
- API параметр min_score: 0.0..1.0 (дополнительное ужесточение)
- Confidence tail delta: 0.18

Важно:
- limit не является процентом.
- Текущий default limit в API: 5 кандидатов.
- Текущий максимальный limit: 20 кандидатов.
- Фактически возвращается 0..limit, потому что слабые кандидаты теперь фильтруются порогом.
