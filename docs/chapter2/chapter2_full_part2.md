## 2.5 Выделение вопросов из транскрипции методами обработки естественного языка

### 2.5.1 Формализация задачи извлечения вопросов

Задача извлечения вопросов из транскрипции диалога относится к классу задач извлечения информации (Information Extraction, IE) [7]. Пусть на входе имеется транскрипция T, представляющая собой упорядоченную последовательность речевых сегментов:

T = {(s₁, t₁^start, t₁^end), (s₂, t₂^start, t₂^end), ..., (s_N, t_N^start, t_N^end)}

где sᵢ — текстовое содержание i-го речевого сегмента, tᵢ^start и tᵢ^end — его начальная и конечная временные метки, N — общее число сегментов.

Требуется найти подмножество Q ⊆ T, каждый элемент которого является вопросом интервьюера:

Q = {qⱼ = (sᵢⱼ, topicⱼ, diffⱼ, tcⱼ)}_{j=1}^{M}

где M ≤ N, topicⱼ ∈ T — тематическая категория из множества T = {Backend, Frontend, DevOps, Algorithms, System Design, ...}, diffⱼ ∈ D = {junior, middle, senior}, tcⱼ — временной код.

Задача декомпозируется на две подзадачи:

1. **Обнаружение вопросов** (Question Detection) — бинарная классификация: f: S → {0, 1}.
2. **Атрибуция вопросов** (Question Attribution) — многоклассовая классификация: g: Q' → T × D.

Специфика диалога технического собеседования делает задачу нетривиальной:

**Отсутствие явной вопросительной формы.** Интервьюер формулирует задания в повелительном наклонении: «Расскажите про паттерн Singleton». Данное явление изучено в теории речевых актов Остина—Серла [8]: иллокутивная сила высказывания не всегда совпадает с синтаксической формой. Речь идёт о косвенных речевых актах (indirect speech acts).

**Разграничение говорящих.** Риторические вопросы кандидата необходимо отличать от вопросов интервьюера. Это требует задачи диаризации на текстовом уровне [9].

**Техническая терминология.** Вопросы содержат специфические термины (GIL, FAISS, CTC, RAFT-консенсус), требующие предметных знаний.

Метрики качества [10]: полнота R = |Q_ext ∩ Q_true|/|Q_true|, точность P = |Q_ext ∩ Q_true|/|Q_ext|, F₁ = 2PR/(P+R). Целевые значения: R ≥ 0,85, F₁ ≥ 0,90.

Рисунок 2.4 — Схема задачи извлечения вопросов

```
Транскрипция T = {(sᵢ, tᵢ)}
  s₁(Интервью)  s₂(Кандидат)  s₃(Интервью) ...
       │                           │
       ▼                           ▼
  Задача обнаружения f: S → {0,1}
  f(s₁)=1 ✓   f(s₃)=1 ✓  (косвенный речевой акт)
       │
       ▼
  Задача атрибуции g: Q' → T × D
  q₁ → (Backend, middle)  q₂ → (Algorithms, junior)
       │
       ▼
  Результат: Q = {qⱼ = (sᵢⱼ, topicⱼ, diffⱼ, tcⱼ)}
```

### 2.5.2 Сравнение подходов к извлечению вопросов

**Правила и регулярные выражения.** f_rule(sᵢ) = 𝟙[∃ r ∈ R : match(sᵢ, r)]. Высокая точность P ≈ 0,95, но низкая полнота R ≈ 0,40 [11].

**CRF** [12]: P(y|x) = (1/Z(x))·exp(Σᵢ Σₖ λₖ fₖ(yᵢ₋₁, yᵢ, x, i)). Требует размеченного корпуса, отсутствующего для данной задачи.

**BERT fine-tuning** [14]: требует ≥2000 размеченных примеров для F₁ > 0,85 [15]. Корпус отсутствует.

**LLM zero-shot** [16]: не требует разметки, понимает прагматику, генерирует структурированный JSON.

Таблица 2.2 — Сравнение подходов

| Подход | Разметка | Recall | F₁ | Косвенные акты | Применимость |
|--------|---------|--------|-----|----------------|-------------|
| Рег. выражения | Нет | 0,35–0,45 | 0,45–0,55 | Нет | Высокая |
| CRF | ≥1500 | 0,65–0,75 | 0,70–0,80 | Частичная | Низкая |
| BERT fine-tune | ≥2000 | 0,75–0,85 | 0,80–0,90 | Да | Низкая |
| LLM zero-shot | Нет | 0,80–0,90 | 0,85–0,93 | Да | Высокая |

### 2.5.3 Промпт-инжиниринг для извлечения вопросов

Промпт-инжиниринг [17] — проектирование инструкции p для максимизации качества:

p* = argmax_{p∈P} E_{q~P_LLM(·|p,T)}[score(q, Q_true)]

Системный промпт:

```
Ты — эксперт по анализу технических интервью. Извлеки ВСЕ вопросы,
которые задаёт интервьюер кандидату. НЕ извлекай вопросы кандидата.
Определи тему (Backend, Frontend, DevOps, Algorithms, System Design,
Databases, Networks, OOP, Architecture, Testing, Security, Mobile,
Data Science, General) и сложность (junior/middle/senior).
Если есть метки времени — укажи таймкод.
Верни JSON-массив:
[{"question": "...", "topic": "...", "difficulty": "...", "timecode": "MM:SS"}]
```

Ключевые элементы: (1) ролевая инструкция (+5–12% F₁ [18]); (2) отрицательное условие [19]; (3) замкнутые множества T и D; (4) JSON-формат (снижение ошибок с 15–20% до 2–5% [20]).

Скользящее окно с перекрытием для длинных транскрипций:

T = ∪_{k=0}^{K-1} T_k, T_k = {sᵢ : i ∈ [k·(L_max−δ), (k+1)·L_max]}

δ = 10–15% от L_max. Дубликаты на границах устраняются при дедупликации (2.6).
